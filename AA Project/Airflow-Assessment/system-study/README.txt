AA STOCK-SYSTEM COMPUTATIONAL CAMPAIGN
19 October 2026. No hardware available. No hardware performance validation.

Open the ONE existing AA project-overview.html, section Stock system iteration.
Read FIRST-PRINCIPLES.txt and output/pdf/AA-first-principles-and-design.pdf.
The PDF is a research note. Equation SVG/PNG files can be reused in slides.

Scope: commercial air supply/source components and a custom low-pressure
nozzle. The EXAIR 3208 reference candidate uses an approximate family map,
not a Jeanoko map or a fitted complete assembly. Exact outlet geometry, stock
adapter, dryer dew point, valve/regulator flow curves and quoted compressor
FAD remain component-selection constraints. No turbines or vessels are custom.

The campaign is bounded to six new cases. It chooses a new paired vortex
setting after the baseline fails the stress margin, then tests low flow,
outlet diameter and a refined mesh. Numerical acceptance gates do not change.
A converged seed on identical geometric boundaries accelerates initialization;
all candidates still receive a new solve and full-field acceptance checks.
Results, failed gates and the exact next-step logic are saved, not overwritten
with a claimed success. Neither a global optimum nor a deployable system is
established. Pending physics are listed in config.json and campaign.json.
This saved CFD campaign fixes 34 C, 100 psig, the 8 mm inlet abstraction and
the agreed 5 x 5 cm target at 20 cm. Changing those reference states requires
a new named campaign and matching postprocessing. Guards reject incompatible
cached fields. The earlier interactive Lean calculator supports general
parameter sensitivity. Stress ranges here can be changed as clearly labeled
one-way sensitivities; geometry/flow changes require new CFD case IDs.

The original overview must exist for that final command. No second overview
is created. For a fresh search, archive existing S0*stock* case directories
and change case names/config explicitly. Do not overwrite historical cases.

The ZIP preserves the relative Airflow-Assessment layout and required common
CFD scripts. Executed case evidence is placed under system-study/evidence/
executed-cases so a fresh optimization/cases tree can be generated by --run.
It includes mesh/solver setup, input files, profile outputs,
audits and logs for the executed cases. Complete native volume fields remain
in the local optimization/cases directories to keep the package small.
The saved campaign is readable without re-running CFD. Native balance gates
must be re-executed from generated fields for a fresh calculation.

PROOFS
../formal-model/ pins Lean 4.31.0 and mathlib v4.31.0. Run lake build there.
The original local setup reused cached dependencies through .lake symlinks.
Those caches are not packaged. The manifest pins portable git dependencies.
System.lean adds area-envelope, nozzle energy and receiver inventory identities.
The numerical EOS, moisture routines, CFD closure and hardware are outside
the Lean proof boundary. See proof-verification.json and actual build.log.

CAD

cad/nozzle-print-mm.stl: millimetre printable body.
cad/nozzle-parametric.scad: editable millimetre parameters.
cad/cad-verification.json: mesh topology, units and corresponding CFD case.
The model is the flow body. Fitted source threads/adapter and final assembly
are not verified. The historical Milton/Jeanoko fit does not prove EXAIR fit.
The printed part has no established pressure rating.
